# รันวิดีโอทั้งหมดเพื่อทำตาราง

ชุดนี้เพิ่มการประมวลผลวิดีโอทั้งหมด ไม่ใช่การนำตารางข้อมูลฝึก 74 วินาทีมาแทนผลทั้งชุด
ยังต้องรันบนเครื่องที่มีวิดีโอจริง จึงจะได้ตัวเลขสำหรับสไลด์ฉบับสุดท้าย

## ทำตามนี้ครั้งเดียว

1. แตกชุด **ใหม่** ไปที่ `E:\CMZ_ALL` ให้ทางเข้าโปรแกรมอยู่ในโฟลเดอร์สั้น ๆ
   อย่าย้ายโปรเจกต์เก่า อย่าย้ายหรือเปลี่ยนชื่อวิดีโอและ workspace เดิม
2. เปิด `START_ALL_VIDEOS_WINDOWS.bat` ในโฟลเดอร์ `CMZ_YOLO_Kit`
   ครั้งแรกจะติดตั้ง Python packages และ PyTorch แยกจากโปรแกรมเดิม
   มีการดาวน์โหลด dependencies ขนาดใหญ่และน้ำหนัก MegaDetector ประมาณ 280 MB
   ไม่อัปโหลดวิดีโอออกจากเครื่อง ไม่ติดตั้งหรือเปลี่ยนไดรเวอร์การ์ดจอ
3. หน้าที่เปิดขึ้นจะอยู่ที่ `http://127.0.0.1:8504`
   ช่อง **1. Existing workspace folder** ใส่ workspace เก่าที่มี `phase2` และโฟลเดอร์ review clips
   ตามภาพก่อนหน้า น่าจะเป็น `E:\mod stardewS\CMZ\CMZ_YOLO_Kit\workspace`
   โปรแกรมจะตรวจว่ามี labels จริงก่อนเริ่ม ถ้าตำแหน่งนี้ไม่ตรง ให้คัดลอกจากช่อง workspace ของโปรแกรมเดิม
4. ช่อง **2. Video folders** ใส่สองบรรทัดนี้ (ใส่ค่าเริ่มต้นไว้แล้ว):

   ```text
   E:\mod stardewS\ชะมดแผงสันหางดำ-20261020T181928Z-1-009 (2)
   E:\mod stardewS\test
   ```

   ถ้ามีวิดีโอต้นฉบับอีกที่ ให้เพิ่มเป็นบรรทัดใหม่ ไม่ต้องแยกไฟล์ตามกล้องเอง
   ไม่ต้องข้ามสามไฟล์เก่า โปรแกรมตรวจสำเนาซ้ำด้วย SHA-256
5. ช่องยืนยันนาฬิกากล้องให้ติ๊กเฉพาะเมื่อเคยตรวจแล้วว่าเวลาชื่อไฟล์และกล้องตรงกันจริง
   หากยังไม่แน่ใจ ให้เว้นไว้ ระบบยังสร้างตารางแยกรายวิดีโอและกล้องได้
   จากนั้นกด **3. Start a NEW full-folder analysis** เพียงครั้งเดียว
6. ปล่อยเครื่องทำงาน เสียบปลั๊กและตั้งไม่ให้เครื่อง Sleep ระหว่างรัน
   ขั้นตอนคือสำรวจทุกไฟล์ → โหลดตัวตรวจจับสัตว์ → ใช้ label เดิมฝึกโมเดลกับกรอบอัตโนมัติ → ประมวลผลวิดีโอทุกช่วง
   ไม่ต้องวาดกรอบหรือติดป้ายใหม่ก่อนเริ่ม โปรแกรมเก็บโมเดลใหม่แยกจากโมเดลเดิม
7. กด **Refresh progress** ดูสถานะ เวลาเหลือเป็นเพียงประมาณการจากความเร็วที่รันจริง
   ถ้าจะหยุด ให้กด **Pause safely** แล้วรอจนเป็น `paused`
   ทำต่อด้วย **Resume selected paused / error run** ไม่ต้อง Start NEW ซ้ำ
8. เมื่อเป็น `complete` กด **Download ALL_VIDEO_RESULTS.zip** แล้วส่ง ZIP นี้กลับมา
   ถ้าเป็น `complete_with_errors` หรือ `error` ส่ง ZIP ที่ได้กลับมาเช่นกัน เพื่อให้ตรวจว่าขาดอะไร
   อย่าใช้ ZIP ระหว่างรันเป็นผลครบทั้งชุด

## ผลที่ได้มีอะไร

- `VIDEO_INVENTORY.csv`: ทุกวิดีโอที่พบ เวลา กล้อง สถานะอ่านไฟล์ และข้อผิดพลาด
- `DUPLICATE_COPIES.csv`: สำเนาที่ซ้ำกันจริง ไม่ประมวลผลซ้ำ
- `KNOWN_VIDEOS_NOT_FOUND.csv`: ชื่อวิดีโอจาก review เดิมที่หาไม่พบในโฟลเดอร์ที่เลือก
- `ALL_WINDOW_PREDICTIONS.csv`: ผลทำนายทีละช่วง 2 วินาทีตลอดความยาวที่อ่านได้
- `PER_VIDEO_MODEL_TABLE.csv`: ตารางเดิน กิน Active ที่โมเดลเสนอ และ Unknown แยกไฟล์
- `PER_CAMERA_HOUR_MODEL_TABLE.csv`: ตารางแยกกล้องและชั่วโมง
- `WINDOW_STATUS_COUNTS.csv`: แยกเหตุผลของช่วงที่ใช้ได้/ไม่ทราบ เช่น ตรวจจับสัตว์ไม่ได้หรือคะแนนจำแนกต่ำ
- `ONE_ANIMAL_HOURLY_ESTIMATES.csv`: ตารางรวมเวลาที่ไม่บวกซ้ำข้ามกล้อง สร้างเฉพาะเมื่อยืนยันนาฬิกาแล้ว
- `HUMAN_CONFIRMED_ONLY.csv`: ข้อมูลตรวจยืนยัน แยกจากค่าทำนาย
- `BATCH_TRAINING_REPORT.json`: ผลฝึกโมเดลสำหรับขั้นตอนใหม่จริง
- `REPLAY_WALKING_CHECKS.json`: รันทดสอบซ้ำกับสามคลิปเดินที่เคยยืนยัน ด้วยระบบใหม่ ไม่ใช่การคัดลอกคะแนนเก่า
- `RESULT_SCOPE.json`: ความครบถ้วนของงานและข้อจำกัดที่ต้องแจ้งในสไลด์
- `AUDIT_SAMPLES.csv` และ `review_samples/`: ตัวอย่างคลิปสั้นจากทุกไฟล์ เพื่อส่งกลับมาตรวจคุณภาพ โดยไม่ต้องส่งวิดีโอทั้งหมด 27 GB

## ข้อจำกัดที่ต้องเข้าใจ

ตัวตรวจจับสัตว์เป็น **MegaDetector V5A ที่ฝึกมาแล้ว** ไม่ใช่ YOLO civet ที่เราฝึกเอง
ระบบใช้การตรวจจับสัตว์ที่ต้นและท้ายของแต่ละช่วง 2 วินาที จึงยังพลาดการปรากฏสั้น ๆ หรือการเปลี่ยนพฤติกรรมได้
Random Forest ใหม่ใช้ข้อมูลยืนยันเดิม แบ่งเป็นช่วงสั้นและใช้กรอบจากตัวตรวจจับเหมือนตอนนำไปใช้จริง
การแบ่งคลิปเดิมเพิ่มไม่ได้ทำให้ได้ตัวอย่างอิสระเพิ่ม โมเดลและตัวตรวจจับยังต้องประเมินกับภาพจริงของชุดนี้

ค่าที่ออกมาคือ **ผลทำนายโมเดล** ไม่ใช่พฤติกรรมที่คนตรวจครบทุกช่วง
คอลัมน์ร้อยละใช้เวลาวิดีโอที่ประมวลผลแล้วเป็นตัวหาร รวม Unknown ด้วย จึงไม่ใช่เปอร์เซ็นต์พฤติกรรมที่ยืนยันแล้ว
โมเดลสองคลาสยังอาจเรียกพฤติกรรมอื่นว่าเดินหรือกินได้ คะแนนสูงไม่ได้แก้ข้อจำกัดนี้
พัก/นอนที่ไม่มีข้อมูลฝึกจะเว้นว่าง ไม่ใส่ 0 ไม่อนุมานจากการเข้าไปในกล่อง
ไม่พบสัตว์ให้เป็น Unknown ไม่ใช่ Inactive

หากตัวตรวจจับกู้ตัวอย่างสำหรับฝึกสองคลาสได้ไม่พอ โปรแกรมจะหยุดและบันทึกเหตุผลใน `TRAINING_SEGMENTS.json`
นี่เป็นการป้องกันการสร้างตารางพฤติกรรมที่ใช้ไม่ได้ ส่ง ZIP ผลกลับมาเพื่อวิเคราะห์จุดที่ติด ไม่ต้องไล่ทำซ้ำเอง

หลังได้ ZIP จากการรันจริง จึงค่อยปรับสไลด์และรายงานให้เป็นผลของวิดีโอทั้งหมด
สไลด์ชุดนำร่องก่อนหน้ายังไม่ใช่ผลประมวลผลครบทั้งชุด
